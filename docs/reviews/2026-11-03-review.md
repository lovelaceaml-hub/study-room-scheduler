# Review 2026-11-03: study-room-scheduler

Whole-repo review of the LV Zion Study Rooms app (https://lvrooms.web.app), done
in a cloud session with three Haiku helpers (frontend, Cloud Functions, CI and
secrets). Their findings were spot-checked against the code before being listed
here; two "unused code" claims turned out wrong and are corrected below. Nothing
was deployed, no live data was read or changed, no secrets were touched.

Status at review time: `main` at `3f9f2df` (2026-10-11). Plan 19 is complete
and no release steps are pending.

## Summary

- The app is in good shape: small, plain JavaScript, no build step, strong tests,
  careful release guards. No exploitable bug was found.
- The biggest item is **dependencies in Cloud Functions**: before this review,
  production dependencies had 1 critical and 4 high advisories. A lockfile
  update (in this PR) clears all of them; 6 moderate remain upstream. It only
  reaches the live site after a backend release (see "Decisions for Anthony").
- The biggest refactor is splitting the 500-line booking sheet and the
  1,000-line Admin page into smaller pieces. Not urgent.

## Ranked refactor suggestions

Ranked by value for effort. None is required for the app to keep working.

1. **Split the booking sheet.** `public/app/booking.js:23` `createBookingSheet`
   is about 500 lines in one function (its `STEPS` table alone is
   `booking.js:214-283`). Split into step modules. Similar but smaller:
   `public/app/mine.js:12` (about 265 lines), `public/app/details.js:13` (about
   155 lines), `public/admin/admin.js` (999 lines in one file).
2. **(Lowered after checking) Shorter timeout on Cloud Function calls.** Booking
   calls (`public/app/store.js:110`) and Admin calls (`public/admin/session.js:137`)
   have no timeout of their own, but Firebase's callable library already gives
   up after 70 seconds, so a hung request does not leave the buttons disabled
   forever, as a helper first claimed. A shorter limit is optional polish.
2b. **Make button labels match their visible text** (see "Accessibility checker
   held at 4.12" under Dependencies). Tried on 2026-11-04 and backed out: making
   the labels start with the visible words was not enough. The time buttons
   (`public/app/booking.js:330`, `public/app/mine.js:196`) put the time and its
   `<small>` line next to each other with no space, so the checker reads
   "1:30 PM30 min"; a space before `<small>` (it is `display: block`, so nothing
   changes on screen) should fix those. The schedule blocks
   (`public/app/main.js:151`) still failed with "Yours" added to the label; the
   cause there is not yet known. Needs its own small change with the browser tests.
3. **Share the sheet summary and banner code.** The reservation summary list is
   built three times (`public/app/details.js:53-66`, `public/app/booking.js:335-345`,
   `public/app/mine.js:167-175`); the connection banner twice
   (`public/app/booking.js:186-193`, `public/app/mine.js:111-120`). The "can act
   now" test repeats at `details.js:77`, `details.js:98`, `booking.js:212`,
   `mine.js:109`.
4. **One copy of the labels and early-end rule.** Admin keeps its own
   `STATUS_LABELS` (`public/admin/admin.js:14`, same as `public/app/text.js:8`),
   purpose labels (`admin.js:113-120` vs `text.js:21-28`), notice wording
   (`admin.js:134-147` vs `text.js:54-64`, wording differs, check it is meant to)
   and early-end rule (`admin.js:573-581` vs `text.js:45-51` and
   `public/shared/availability.js:269`). Move the shared ones to `public/shared/`.
5. **(Done in this PR) Guard a missing reservation in My reservations.** `public/app/mine.js:265`
   and `:268` read `item.id` after `find()`; if the reservation vanished (for
   example cancelled on another device) the user sees a raw "Cannot read
   properties of null" message instead of a friendly one.
   Follow-up nit from the independent review: the guard returns to the list but
   leaves any earlier error text showing, where the Back button clears it. Use
   the same path as Back when this is next touched.
6. **Do not load demo code on the live site.** `public/app/store.js:7` and
   `public/tv/tv.js:6` import the demo backend even without `?demo=1`. A dynamic
   import would make the normal page load smaller.
7. **TV refetch loop.** `public/tv/tv.js:157-159` calls `load()` from `render()`,
   which runs every 30 seconds (`tv.js:270`); a day with no room schedule
   refetches every 30 seconds instead of every minute. Minor.
8. **Server code tidy-ups** (only take effect after a backend release, and each
   one makes the weekly drift check report "different" until then, so batch
   them with a real backend change):
   - (Done in this PR) `functions/lib/actions.js:136-148` built `record(...)` twice
     per branch; the `RECORD_LIMIT` comment (`actions.js:18-19`) now says records
     past the limit would not be shown.
   - `functions/lib/guard.js:105-110` hashes by hand; could reuse `sha256` (`guard.js:21`).
   - `scripts/reservations.mjs:64` repeats `unitName` from `functions/lib/bookings.js:41`.
   - Try/catch error conversion repeated at `functions/index.js:32-38` and
     `functions/lib/actions.js:346-350`.
   - Keep `holder.purpose !== HOLD` at `functions/lib/bookings.js:131`: a helper
     called it redundant, but it is the explicit "Admin holds are never taken"
     guard and costs nothing.
9. **Workflow duplication.** Node setup plus `npm ci`, Playwright install, the
   test gate, the deploy-key write and removal, and the guard self-test repeat
   across `.github/workflows/tests.yml`, `firebase-preview.yml`,
   `firebase-release.yml` and `firebase-backend-release.yml`. A composite
   action would remove about 60 lines. The two guard scripts repeat their
   `fail`/`expect` helpers (`.github/scripts/deploy-guard.sh:29-45`,
   `.github/scripts/backend-guard.sh:49`, `:327-338`), and
   `backend-guard.sh:113-147` is a 35-line inline `node -e` that would be easier
   to test as its own file.
10. **Small script fixes.** `ops/cloud-shell/backend-deploy-wif.sh:152-158` leaves
    a temp file behind on failure (use a `trap`); `backend-deploy-wif.sh:233`
    reuses positional arguments; `.github/workflows/firebase-backend-release.yml:188`
    leaves `$NAMES` unquoted (the names are validated against the pinned list
    first, so this is style, not risk).

Corrected helper claims: `roomStatus` and `nextOpenMinute` in
`public/tv/status.js:22` and `:34` are **not** dead code; `test/tv.rules.test.mjs:6`
uses them.

### Server behaviour worth a decision (not bugs)

- **No booking rate limit.** `functions/lib/actions.js:108-148` and
  `functions/index.js:49-55`: anyone can sign in anonymously again and keep
  booking. There is no App Check or per-device limit. For a church app this is
  probably fine; App Check would be the fix if abuse ever happens.
- **Admin PIN lockout is global.** `functions/lib/guard.js:127` and `:155`: 20
  wrong PINs from anywhere lock Admin sign-in for everyone for 15 minutes
  (`functions/lib/config.js:112-118` says this is intended). It protects the PIN
  but lets a stranger lock Admin out for a while.
- **Admin session extends even when an action fails** (`functions/index.js:137-150`). Harmless.
- **Notes for deleted bookings are never removed.** `functions/lib/actions.js:342-353`
  saves a note without checking the booking exists, and cleanup
  (`actions.js:310-321`) only removes notes of bookings it deletes. Admin-only, low.
- **Schedule reads stop at 2,000 records** (`functions/lib/actions.js:43`, `:49`).
  Far above real use; the comment at `actions.js:18-19` now says so.

### Test gaps

- No test for saving a note on a booking that does not exist, restoring an
  ended booking (`functions/lib/actions.js:278`), the 2,000-record limit, or a
  failed Admin action leaving the session unextended.
- `scripts/reservations.mjs` has no test (it is read-only).

Vulnerabilities (`npm audit`):

- **functions, runtime dependencies:** before: 1 critical (`proxy-addr`), 4 high
  (`@fastify/busboy`, `@grpc/grpc-js`, `body-parser`, `brace-expansion`), 11
  moderate. After this PR: 0 critical, 0 high, 6 moderate (`gaxios`,
  `gcp-metadata`, `glob`, `google-gax`, `minimatch`, `rimraf`), all held back
  inside firebase-admin's own Google libraries; they clear when Google updates
  firebase-admin.
- **functions, test-only dependencies:** 5 high remain, all through `firebase`
  11 (`@grpc/grpc-js`). They only run in the Firestore emulator test. Fix needs
  the `firebase` 13 and `@firebase/rules-unit-testing` 6 major upgrades, which
  should be their own change with the emulator test run.
- **root:** 0 vulnerabilities.

**Accessibility checker held at 4.12.** With `@axe-core/playwright` 4.14.0
(tried in this PR), two browser tests fail on a stricter check,
`label-content-name-mismatch`: the screen-reader name of some buttons does not
contain their visible text. It flags the member schedule (`test/app.smoke.mjs:157`)
and the "End early" step of My reservations (`test/app.smoke.mjs:809`). Likely
spots: `public/app/main.js:151` (booked block label), `public/app/mine.js:196`
and `public/app/booking.js:330` (time buttons whose label starts with other
words than the visible time). Same tests pass with 4.12.1, checked locally.
`package.json` now holds the checker at `~4.12.1`. Follow-up: make each label
begin with the button's visible text, then lift the hold. This is a real
improvement for screen-reader and voice-control users, so it is ranked as
refactor 2b below.

Other version notes:

- GitHub Actions: `actions/checkout@v7` and `actions/setup-node@v7` are current
  but pinned by tag; `actions/setup-java@v4` (`.github/workflows/tests.yml:54`,
  `.github/workflows/firebase-backend-release.yml:82`) is behind; only

- Node 22 everywhere, matching `functions/package.json:6`. Node 22 reaches its
