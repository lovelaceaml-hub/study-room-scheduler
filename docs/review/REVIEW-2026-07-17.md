# Code review — July 17, 2026

A multi-agent review team (correctness, security, UI, UX, accessibility, housekeeping reviewers across three model tiers) audited the whole app; every finding was then challenged by an independent skeptic agent. 38 findings were raised; 24 were confirmed.

## Fixed immediately (14)

- **Admin PIN lockout is trivially bypassed by rotating anonymous Firebase UIDs** (functions/index.js:60, high)
- **`nav` positioning contradicts across generations (sticky top:70 → absolute top:10/right:68), base mobile override also dead** (index.html:440, high)
- **Booking dialog's accessible description is silently blank for the primary open-booking flow** (app.js:1264, high)
- **Admin PIN brute-force rate limiter is keyed on attacker-controllable anonymous UID** (functions/index.js:60, medium)
- **No rate limit or per-user cap on booking creation lets an anonymous user flood/deface the schedule** (functions/index.js:444, medium)
- **'My reservations' date selector is decorative — it doesn't filter the list, but looks like it should** (app.js:992, medium)
- **No on-screen instruction that tapping a second, later time extends the reservation** (app.js:933, medium)
- **Nothing in the booking popup or calendar tells a member, before they submit, whether their request will be auto-approved or held for manual review** (app.js:1257, medium)
- **Keyboard focus is not restored after closing the booking modal opened via the member-calendar "Continue" flow** (app.js:1132, medium)
- **Tab bar uses the ARIA Tabs pattern (role=tablist/tab) but has no keyboard arrow-key navigation, only touch swipe** (app.js:2036, medium)
- **The live-updating schedule region has no aria-live announcement — only the transient banner strip does** (index.html:585, medium)
- **Failed admin PIN entry is not announced to assistive tech and focus is dropped after the re-render** (app.js:1345, medium)
- **Outdated documentation about deployment status** (docs/USER-MANUAL.md:6, medium)
- **selectMemberSlot mutates ui.memberSelection in place BEFORE the full-slot validation, so a rejected range corrupts stored state and bypasses the guard** (app.js:1100, low)
